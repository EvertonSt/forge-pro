1. Introduction

What is Forge-Pro?

Forge-Pro is an AI-native, self-QA'd marketplace for premium website templates and UI components. It provides:

  • 10 production-ready templates — Each worth $2,000–$5,000 in design quality
  • Automated QA gate — Validates responsive design, accessibility, SEO, and performance
  • One-click deployment — Free hosting on Vercel or Netlify
  • Vendor portal — Submit, manage, and sell your templates
  • Desktop app — Windows installer for local preview

5. Customization Guide

Brand Colors

Every template uses CSS custom properties for easy theming. Edit the :root section in the global CSS file:

/* templates/nimbus/src/styles/global.css */
:root {
  --accent: #e63946;        /* Primary brand color */
  --accent-hover: #c1121f;  /* Hover state */
  --bg: #faf9f7;            /* Background */
  --text: #1a1a2e;          /* Text color */
  --border: #e8e6e1;        /* Borders */
}

💡 Pro Tip

Use coolors.co to generate harmonious color palettes. Copy the hex values into the CSS variables.

Typography

Fonts are loaded via Google Fonts in the layout file. To change fonts:

/* In Layout.astro or layout.tsx */


/* Then update CSS variables */
:root {
  --font-serif: 'Your Font', Georgia, serif;
  --font-sans: 'Inter', system-ui, sans-serif;
}

Replace placeholder content with your own:

Images

All templates use Unsplash for placeholder images. Replace with your own:

<!-- Before -->
<img src="https://images.unsplash.com/photo-..." alt="..." />

<!-- After -->

For production, convert images to WebP format and add proper width and height attributes to prevent layout shift.

11. Supabase Configuration

Forge-Pro uses Supabase for authentication, database, and real-time features. The platform runs in demo mode without Supabase, but production use requires a Supabase project.

When Do You Need Supabase?

Template marketplaceDemo data (in-memory)Real vendor submissions
Vendor authenticationAuto-login as demo vendorEmail/password + OAuth
Admin panelDemo dataReal vendor management
QA gateSimulated resultsReal automated QA
Template uploadsIn-memory onlyPersistent storage
Payments (Stripe)Test modeReal transactions

Templates Do Not Need Supabase

All 10 templates are fully static and use mock/localStorage data. Supabase is only needed for the main Forge-Pro marketplace app (apps/app).

Step 1: Create a Supabase Project

  1. Go to supabase.com and sign up (free tier)
  2. Click New Project
  3. Choose a name (e.g., forge-pro), set a strong database password
  4. Select a region close to your users
  5. Wait for the project to initialize (~30 seconds)

Step 2: Get Your Keys

In the Supabase Dashboard → Settings → API:

KeyWhere to Find ItPurpose
SUPABASE_URLProject URLDatabase API endpoint
SUPABASE_ANON_KEYProject API → anon/publicServer-side database access
SUPABASE_SERVICE_ROLE_KEYProject API → service_roleAdmin access (bypasses RLS)
NEXT_PUBLIC_SUPABASE_URLSame as SUPABASE_URLClient-side browser access
NEXT_PUBLIC_SUPABASE_ANON_KEYSame as SUPABASE_ANON_KEYClient-side browser access

Two Sets of Keys

Forge-Pro uses both naming conventions. The NEXT_PUBLIC_ prefixed vars are for client-side code (browser). The unprefixed vars are for server-side code (API routes, server components). Set all 5 on Vercel.

Keep Keys Secret

Never commit SUPABASE_SERVICE_ROLE_KEY to Git. It bypasses all security rules. Use Vercel environment variables instead.

Step 3: Set Up the Database Schema

Forge-Pro includes migration files in supabase/migrations/. Run them in order (schema first, then RLS).

Important: Run Schema Before RLS

The RLS migration references tables created by the schema migration. If you run them out of order, you will get relation "public.profiles" does not exist errors.

Method 1: Copy to clipboard and paste into Supabase SQL Editor

# Windows PowerShell — copies schema SQL to clipboard
cd forge-pro\supabase\migrations\20260815000000_schema.sql | clip
# Paste into Supabase SQL Editor → Click Run → Wait for "Success"

# Windows PowerShell — copies RLS SQL to clipboard
cd forge-pro\supabase\migrations\20260815000001_rls.sql | clip
# Paste into Supabase SQL Editor → Click Run → Wait for "Success"

Method 2: Use the Supabase CLI

# Install Supabase CLI
npm i -g supabase

# Link to your project
supabase link --project-ref YOUR_PROJECT_REF

# Run migrations
supabase db push

Step 4: Configure Row Level Security (RLS)

The RLS migration (Step 3, second file) adds security policies that ensure:

  • Vendors can only see/edit their own submissions
  • Admins can see all submissions and manage vendors
  • Public users can only read published templates
  • API endpoints validate authentication before mutations

Step 5: Set Environment Variables on Vercel

Add these in Vercel Dashboard → Settings → Environment Variables, or via PowerShell:

# PowerShell commands to set all env vars
cd "C:\AI\Freebuff Desktop\GitHub Projects\forge-pro"

# Server-side vars (store as sensitive)
vercel env add SUPABASE_URL production               # Paste: https://xxx.supabase.co
vercel env add SUPABASE_ANON_KEY production            # Paste: your anon key
vercel env add SUPABASE_SERVICE_ROLE_KEY production    # Paste: your service_role key

# Client-side vars (store as non-sensitive)
vercel env add NEXT_PUBLIC_SUPABASE_URL production     # Paste: same URL as above
vercel env add NEXT_PUBLIC_SUPABASE_ANON_KEY production # Paste: same anon key as above

Step 6: Update turbo.json (Required)

Turbo needs to know about the env vars to pass them to the build. Open turbo.json and add the Supabase vars to globalEnv:

// turbo.json
{
  "globalEnv": [
    "SUPABASE_URL",
    "SUPABASE_ANON_KEY",
    "SUPABASE_SERVICE_ROLE_KEY",
    "NEXT_PUBLIC_SUPABASE_URL",
    "NEXT_PUBLIC_SUPABASE_ANON_KEY"
  ],
  ...
}

Why Both Naming Conventions?

The DB package (@forge-pro/db) reads SUPABASE_URL (no prefix). The Next.js app reads NEXT_PUBLIC_SUPABASE_URL for client components. Both must be set.

Step 7: Enable OAuth (Optional)

To allow users to sign in with Google/GitHub:

  1. In Supabase Dashboard → Authentication → Providers
  2. Enable Google or GitHub
  3. Add your OAuth credentials from the provider's developer console
  4. Set the callback URL to: https://YOUR_PROJECT.supabase.co/auth/v1/callback

Step 8: Deploy

cd forge-pro
vercel --prod

12. Troubleshooting

Common Issues

"Module not found" error

Solution: Run npm install again. If that doesn't work, delete node_modules and reinstall.

rm -rf node_modules
npm install

Port already in use

Solution: Kill the process using the port, or specify a different port:

# Astro
npm run dev -- --port 4400

# Next.js
npm run dev -- -p 3400

Build fails with TypeScript errors

Solution: Check the error message. Common fixes:

  • Add missing type imports
  • Fix JSX props (use camelCase for SVG attributes: stroke-width → strokeWidth)
  • Ensure all dynamic routes have generateStaticParams()

Theme toggle not working

Solution: Ensure the no-flash script is in the <head>:

<script>
  (function() {
    var s = localStorage.getItem('theme');
    if (s === 'dark' || (!s && window.matchMedia('(prefers-color-scheme: dark)').matches))
      document.documentElement.setAttribute('data-theme', 'dark');
  })();
</script>

Vercel deployment fails

Solution: Check that vercel.json has the correct outputDirectory:

  • Astro: "outputDirectory": "dist"
  • Next.js: "outputDirectory": ".next"
  • SvelteKit: remove outputDirectory (adapter-auto handles it)

"routes-manifest.json" not found (Next.js)

Solution: This happens when outputDirectory is set to "out" but Vercel needs ".next". Vercel's Next.js builder expects the standard .next/ build output, not the static export out/ directory.

// vercel.json — correct for Next.js on Vercel
{
  "outputDirectory": ".next"
}

"--name" option is deprecated

Solution: Remove --name from vercel commands. Vercel CLI 59+ infers the project name from the directory name automatically.

# Old (deprecated)
vercel --yes --prod --name nimbus

# New (correct)
vercel --yes --prod

PowerShell: script won't run

Solution: PowerShell cannot run .sh scripts natively. Use one of:

  • .\scripts\deploy-vercel.ps1 (PowerShell version)
  • bash .\scripts\deploy-vercel.sh (if Git Bash is installed)
  • Open Git Bash and run from there

Build succeeds locally but fails on Vercel

Solution: Common causes:

  • Missing dependencies: Ensure package.json lists all needed packages (not just devDependencies)
  • Node version: Vercel uses Node 20+ by default. Add "engines": {"node": ">=22"} to package.json if needed
  • Monorepo issues: The root vercel.json uses pnpm install --frozen-lockfile. Ensure pnpm-lock.yaml is committed
  • Missing generateStaticParams: Dynamic routes (e.g., [id]) need this function when using static export

SvelteKit deploy warning: "Could not detect a supported production environment"

Solution: This is a harmless warning from @sveltejs/adapter-auto. On Vercel, the adapter auto-detects the platform and works correctly. Ignore this warning — the build still succeeds.

Template works locally but shows 404 on deployed URL

Solution: Check that:

  • The build completed successfully (check Vercel deployment logs)
  • outputDirectory points to the correct build output
  • All internal links use relative paths (/about not http://localhost:4321/about)
  • Dynamic routes have generateStaticParams() for static export

Custom Domains

To use your own domain instead of *.vercel.app:

  1. Buy a domain (Namecheap, Cloudflare, etc. ~$10/year)
  2. In Vercel Dashboard → your project → Settings → Domains
  3. Add your domain (e.g., nimbus.yourdomain.com)
  4. Configure DNS as instructed by Vercel (CNAME or A record)
  5. SSL is automatic and free

Team Access

All projects are under the everton-qa team. To add team members:

  1. Vercel Dashboard → Settings → Members
  2. Invite by email
  3. Free tier supports unlimited team members for personal accounts
